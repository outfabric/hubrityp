**RESOLVED (QA-2, 2026-06-04): `closeBtnText` no-op fixed via `onPopoverRender`.** `closeBtnText: 'Pular tour'` is a NO-OP in Driver.js 1.4.0 (hardcodes `&times;` + `aria-label="Close"`, never reads `closeBtnText`). The fix (`relabelCloseButton` in dashboard-tour-impl.tsx) overrides `popover.closeButton.textContent` + `aria-label` to "Pular tour" on every render — confirmed PASS on all 5 steps (text + aria), still dismisses, Esc still works.
- **QA-2 overflow MÉDIO (RESOLVED in QA-3, commit `c3552d3`):** the original relabel set text only, no CSS → "Pular tour" overflowed the ~32×28px glyph box and spilled outside the card. The globals.css fix (`.driver-popover .driver-popover-close-btn` width/height:auto, white-space:nowrap, 0.8125rem, brand-700; `.driver-popover-title` padding-right:4.5rem) FIXES the overflow: QA-3 measured `overflowsBox=false`, single line, brand-700, inside the card on all 5 steps + 375px.
- **QA-4 top-left/title-OVERLAP MÉDIO (RESOLVED in QA-5, 2026-06-04):** the close control rendered TOP-LEFT on top of the title because Driver's `all:unset` cleared the right-anchor and the rule set `right`/`top` but never re-asserted position. **Final fix (validated QA-5): the rule now has `position: absolute !important; left: auto !important; top: var(--ds-space-3); right: var(--ds-space-3)`** (token `--ds-space-3`=0.75rem=12px, NOT the undefined `--space-3`). QA-5 measured on all 5 steps + 375px: position absolute, top:12px right:12px, insideBox, oneLine, brand-700, dismiss+Esc work, stamp persists. PASS.
  - **Overlap false-positive gotcha when probing:** the title has `padding-right:4.5rem` (72px reservation). A whole-element bounding-box overlap test reports `overlapTitle=true` even when correct, because the padding box extends under the button. To judge real overlap, measure the title's CONTENT box (border-box right − paddingRight) or the rendered-text Range rect vs `btn.left` — `titleTextOverlapsBtn` is the truthful signal (false = OK).
- **Live `rm -rf /app/.next` corrupts the running dev server** (missing routes-manifest/build-manifest, stale ESM `_document.js` → persistent 500 on every route). Do NOT wipe `.next` live to bust stale CSS; use `docker compose restart app` (rebuilds Turbopack clean) or a content edit, then verify the SERVED chunk (`/_next/static/chunks/[root-of-the-server]__*.css`) contains the rule.
- **Stale-CSS cold-start gotcha:** the dev server can serve a CSS bundle missing a just-committed globals.css change (grep served `[root-of-the-server]__*.css` for the rule = 0 hits) even though the rule is on disk and the commit predates container start. A content edit forces Turbopack to recompile and the fix appears. If a CSS fix looks "not applied", force a recompile/restart before judging it.

**Local browser-auth workaround (CRITICAL for QA, not a product bug):** docker-compose sets `NEXT_PUBLIC_SUPABASE_URL=http://supabase_kong_hubrityp:8000` (internal Docker hostname). The browser can't resolve it AND CSP blocks it → form login from the host browser FAILS (stuck on /login, realtime ws CSP errors). Workaround that worked: create users via GoTrue admin API (needs user_metadata fullName/crpNumber/crpUf/termsAcceptedAt/privacyAcceptedAt/sensitiveDataConsentAt — `handle_new_user` trigger requires them), password-grant to get a session, then inject the SSR cookie directly. Cookie name = `sb-supabase_kong_hubrityp-auth-token` (storageKey = `sb-${hostname.split('.')[0]}-auth-token`). Value = `base64-` + base64url(JSON.stringify(session{access_token,token_type,expires_in,expires_at,refresh_token,user})). Fits one chunk (<3180). Set via `playwright-cli cookie-set <name> <val> --domain=localhost --path=/`. Middleware then accepts it server-side. Set profiles status='active' + crp_validated_at directly to pass the onboarding gate.

Service role / anon keys are the supabase-demo defaults in .env.local. DB: `docker exec supabase_db_hubrityp psql -U postgres -d postgres`. Migrations may need running first: `DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres npx tsx scripts/db-migrate.ts`.
