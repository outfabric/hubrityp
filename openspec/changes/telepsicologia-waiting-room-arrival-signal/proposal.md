## Why

The telepsychology spec (`telepsicologia-psychologist-ui`, Requirement "Waiting room shows patient status and admit button", Scenario "Patient arrives in waiting room") promises that the psychologist sees "Paciente aguardando" **when the patient actually enters the waiting room**. The implementation does not satisfy this: the badge in `in-call-view.tsx` is driven by `room.status === 'pending' && participantCount <= 1`, but `room` is a static server-rendered prop and `pending` is the default state of every room from the moment it is minted (~1h early by the `auto-create-room` Inngest job). The patient is also deliberately kept OUT of Stream until admission (the `/api/video/join` handler only returns the Stream JWT when `status==='active'`), so `participantCount` never reflects the patient either. Result: the badge shows whenever the psychologist is alone in a pending room — regardless of whether any patient has arrived. There is no real arrival signal, and the audit trail cannot measure how long a patient waited (`video_session_logs` only records `patient_joined` at admit time).

This is a spec-vs-implementation divergence (the correct behavior is already specified), not new scope. The presence model below also closes three correctness gaps that a naive "set-once arrival flag" would leave open: (a) patient arrives then leaves → badge stays "aguardando" forever; (b) patient arrives early and leaves immediately → permanent false-positive badge; (c) badge fails to clear after admit because `room.status` is a static prop and an arrival-only broadcast never signals the `active` transition.

## What Changes

- **Record patient arrival AND liveness server-side** in `/api/video/join` (`waiting` branch). Two timestamps on `video_rooms` with distinct roles:
  - `patient_waiting_at` — **immutable first-arrival marker**, set once on the first waiting poll (audit + wait-time).
  - `patient_last_seen_at` — **mutable liveness heartbeat**, updated on **every** waiting poll (reuses the existing 10s patient poll; no new patient-side timer).
  On the first arrival, also append the **distinct** one-time `patient_arrived` event to `video_session_logs` (distinct from the admission `patient_joined` event, so wait time is measurable). The route stays public/token-gated and continues to expose no internal IDs and no new response fields.
- **Deliver the heartbeat to the psychologist via Supabase Realtime, owner-scoped**, using **Broadcast from Database on a private channel** (not Postgres Changes). A SECURITY DEFINER trigger on `video_rooms` broadcasts a **minimal, secret-free** payload (`room_id`, `last_seen_at`) on the private topic `video-room:<roomId>` whenever `patient_last_seen_at` changes (`NEW.patient_last_seen_at IS DISTINCT FROM OLD.patient_last_seen_at`). Authorization is enforced by an RLS policy on `realtime.messages` confirming the topic's room is owned by `auth.uid()`. (Rationale: Postgres Changes streams the FULL row, and `video_rooms` holds `patient_jwt` / patient & partner tokens — broadcasting those to the psychologist's browser is an unacceptable credential exposure. Broadcast volume is safe: a 10s heartbeat is 0.1 msg/s vs. Supabase's documented 10 msg/s-per-channel Broadcast limit. See design.md.)
- **Drive the badge by heartbeat freshness, not a latch.** A named TTL constant (`WAITING_PRESENCE_TTL_MS = 30_000`, tolerating ~2 missed 10s polls) defines presence. The psychologist UI seeds `lastSeenAt` from the server-rendered `patient_last_seen_at`, resets a freshness timer on each heartbeat broadcast, and re-evaluates on an interval so the badge **auto-clears after the TTL** once heartbeats stop. Badge condition ≈ `room.status === 'pending' && isPatientPresent`, where `isPatientPresent = lastSeenAt != null && (now − lastSeenAt) < TTL`. The `participantCount` heuristic is removed.
- **Clear the badge immediately on admit.** On `Admitir` success, flip local state (treat the room as no longer `pending`) so the badge disappears instantly; the heartbeat naturally stops (the admitted patient's poll hits the `active` branch and is no longer a `waiting` poll), so the TTL is the backstop. The existing "admit, then patient returns within expiry" behavior (durable `status='active'` → returning poll gets the JWT) is preserved.
- **Signal patient departure for immediate clearing (mandatory).** The patient waiting-room view fires `navigator.sendBeacon` on `pagehide` (preferred over `beforeunload`/`unload` for mobile + bfcache reliability) to a new dedicated, public-but-token-gated `POST /api/video/depart` route. The beacon body carries the same 64-char token as the credential (sendBeacon sends no custom auth headers). On a valid departure for a room still in `waiting`/`pending`, the server clears `patient_last_seen_at` back to NULL — the same heartbeat trigger fires on that change and broadcasts the cleared state on the same private `video-room:<roomId>` channel, so the psychologist's badge clears **at once** instead of waiting out the TTL. The immutable first-arrival audit marker `patient_waiting_at` is NOT cleared. The endpoint stays rate-limited and exposes nothing (sendBeacon ignores the response anyway).
- **TTL remains the guaranteed backstop.** sendBeacon is mandatory to *implement*, but correctness does NOT *depend* on any single beacon firing: if a beacon is lost (crash/network), the staleness TTL still clears the badge. A departure followed by the patient reopening re-establishes presence cleanly — the next waiting poll re-stamps `patient_last_seen_at`.
- **Fix the stale, misleading comment** in `in-call-view.tsx` (the "participants beyond the psychologist … in the lobby" fossil from the original `participantCount > 0` design that the poll-only patient flow silently invalidated).
- **Bonus capability unlocked:** wait-time is now measurable from the `patient_arrived` → `patient_joined` delta.

## Capabilities

### New Capabilities

(none — this change modifies existing telepsychology capabilities)

### Modified Capabilities

- `telepsicologia-data-model`: add the `patient_waiting_at` (immutable first-arrival) and `patient_last_seen_at` (mutable liveness heartbeat) columns to `video_rooms`; add `patient_arrived` to the `video_session_logs` event-type CHECK; introduce the Broadcast-from-Database trigger on `video_rooms` (heartbeat on `patient_last_seen_at` change) and the owner-scoped RLS policy on `realtime.messages` that authorizes the private channel.
- `telepsicologia-patient-join`: the `/api/video/join` `waiting` branch SHALL update `patient_last_seen_at` on every poll and set `patient_waiting_at` + a one-time `patient_arrived` log only on the first arrival; AND a new token-gated `POST /api/video/depart` route SHALL clear `patient_last_seen_at` (leaving `patient_waiting_at` intact) on a valid departure beacon, with the waiting-room view emitting that beacon on `pagehide`. Both routes continue to expose no internal IDs, JWTs, patient PII, or new response fields.
- `telepsicologia-psychologist-ui`: the waiting indicator SHALL be driven by heartbeat freshness against a named TTL (auto-clearing when heartbeats stop), seeded from the server-rendered `patient_last_seen_at`, delivered over an owner-scoped Realtime private channel; it SHALL clear immediately on admit AND immediately on a received departure signal (cleared heartbeat), with the TTL still covering the no-beacon case, and SHALL replace the static-`pending` / `participantCount` heuristic.

## Impact

- **Schema / DB:** `src/shared/db/schema/telepsicologia/tables.ts` (two new columns + new CHECK value), `policies.ts` (new `realtime.messages` authorization policy), a new Drizzle migration (columns, CHECK update, heartbeat trigger function + trigger, `realtime.messages` RLS policy — appended manually per the migrations README).
- **Route Handlers:** `src/app/api/video/join/route.ts` (heartbeat `patient_last_seen_at` on every waiting poll; set-once `patient_waiting_at` + one-time `patient_arrived` log on first arrival); NEW `src/app/api/video/depart/route.ts` (token-gated, rate-limited; clears `patient_last_seen_at` to NULL on a valid departure for a `waiting`/`pending` room; leaves `patient_waiting_at` intact; empty/opaque response).
- **Module / UI:** new owner-scoped Realtime presence hook under `src/modules/telepsicologia/` (private channel, TTL freshness timer; treats a cleared/null heartbeat as immediate absence), a `WAITING_PRESENCE_TTL_MS` constant, `video-call-client.tsx` / `in-call-view.tsx` (heartbeat-driven badge, immediate post-admit clear, comment fix), mandatory `sendBeacon`-on-`pagehide` departure signal in `waiting-room-view.tsx`, barrel export.
- **Security:** introduces the project's first private Realtime channel (RLS on `realtime.messages` + `{ config: { private: true } }`); no PII/JWT/token crosses the wire (payload is `room_id` + `last_seen_at`, possibly null); subscription is owner-scoped; both public routes (`join`, `depart`) remain token-gated and rate-limited and expose nothing.
- **Dependencies:** Supabase Realtime (already in use for notifications/ai-transcription). No new external dependency, no Stream cost change (patient still never enters Stream pre-admit).
- **Tests:** unit (badge freshness/TTL via fake timers, presence hook incl. cleared-heartbeat → immediate absence, `pagehide` beacon fires with token), integration (every-poll heartbeat + set-once arrival/log; depart clears `patient_last_seen_at` and preserves `patient_waiting_at`, idempotent, rate-limited, invalid token rejected, leaks nothing; heartbeat trigger fires on `last_seen_at` change including the clear; RLS on `realtime.messages` rejects non-owner), E2E seeded (patient poll → badge appears; departure beacon → badge clears immediately; no-beacon → badge auto-clears after TTL; clears on admit).
