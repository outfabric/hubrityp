## 2. Recurrence Generation — Pure Function & Validators

- [x] 2.1 Create `src/modules/sessions/lib/generate-recurrence-instances.ts` — pure function `generateRecurrenceInstances(rule: RecurrenceRule): Date[]`. Input: `{ frequency, daysOfWeek, startDate, endDate?, occurrenceCount?, isIndefinite, materializationWindowMonths? }`. Returns array of dates. Handles weekly (N weeks apart), biweekly (2 weeks), monthly (same day-of-month), custom (specific days). For indefinite: materializes up to `MAX_MATERIALIZED_SESSIONS = 104` dates within `materializationWindowMonths` (default 24). Skips no dates (conflict detection is caller's responsibility)
- [x] 2.2 Create `src/modules/sessions/lib/recurrence-schema.ts` — Zod schemas: `recurrenceFormSchema` (frequency enum, daysOfWeek int array, startDate, endDate optional, occurrenceCount optional, isIndefinite boolean; refinements: endDate OR occurrenceCount OR isIndefinite must be set; daysOfWeek required when frequency is weekly/custom; occurrenceCount min 2 max 104), `coupleSessionSchema` (patient_ids uuid array max 2, all distinct), `lateRecordSchema` (is_late_record boolean, date must be in past when true)
- [x] 2.3 Create `src/modules/sessions/lib/compute-edit-scope.ts` — pure function `computeEditScope(scope: 'this' | 'this_and_future' | 'all', sessionId, allSeriesSessions): { toUpdate: SessionId[], toDetach: SessionId[], newRecurrenceEndDate?: Date }`. Given a scope choice, determines which session IDs to update. Filters out past/completed sessions for 'all' scope. For 'this': returns only the target session to detach. For 'this_and_future': returns target + all sessions after it

## 3. Server Actions — Recurring Sessions

- [x] 3.1 Create `src/modules/sessions/server/create-recurring-session.ts` — Server Action: validates input with recurrenceFormSchema + session form schema, authenticates via session, creates `session_recurrences` row, calls `generateRecurrenceInstances`, batch-inserts N `sessions` rows with shared `recurrence_id` in a single transaction. Returns `{ recurrenceId, sessionCount }`. Handles conflict detection: queries existing sessions in the date range, returns warnings for overlapping dates (does not block, per RN-03.01)
- [x] 3.2 Create `src/modules/sessions/server/edit-recurring-session.ts` — Server Action: receives `{ sessionId, scope: 'this' | 'this_and_future' | 'all', updates }`. Validates with Zod, authenticates. For 'this': sets `recurrence_id=NULL` on target, applies updates. For 'this_and_future': splits recurrence (update old end_date, create new recurrence, reassign sessions), applies updates to reassigned sessions. For 'all': applies updates to all future scheduled/confirmed sessions in the series
- [x] 3.3 Create `src/modules/sessions/server/cancel-recurring-session.ts` — Server Action: receives `{ sessionId, scope, cancellationData }`. For 'this': cancels single session (status='cancelled'). For 'this_and_future': cancels all from target onward, updates recurrence end_date. For 'all': cancels all future non-completed sessions
- [x] 3.4 Create `src/modules/sessions/server/create-couple-session.ts` — Server Action: validates `patient_ids` (max 2, distinct, both owned by psychologist via RLS), sets `patient_id` to first entry, `patient_ids` to full array. Can be combined with recurrence (couple + recurring). Uses `coupleSessionSchema`
- [x] 3.5 Create `src/modules/sessions/server/create-late-record.ts` — Server Action: validates that date is in the past, sets `is_late_record=true`, `status='done'`. Skips reminder event dispatch. Still validates conflict detection (RN-03.01)
