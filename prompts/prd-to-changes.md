Read the PRD content in `docs/prd/13-patient-session-history.md` to understand the functionalities that will be implemented on the platform. You must create changes to implement the functionalities described in PRD 13. Each change must have Backend and Frontend specifications, as it will be implemented by a full-stack code agent. In the Frontend specifications, you must use the system's Design System definitions, described in the file `docs/design-system/rules.md`, to maintain visual consistency across the platform. If necessary, you can use MCP Context7 to consult usage and integration details with any library/tool, to precisely define the related technical specifications. Furthermore, each change must specify unit, integration and E2E tests when relevant and recommended to test the changes, in order to ensure the correct functioning of the functionalities in production.

**Aspect to consider when developing changes:** Automated tests are expected to be implemented immediately after the code change that prompted them, to ensure that the code agent still has the context of the change related to the test, preventing it from having to consult the changes again before writing the tests.
